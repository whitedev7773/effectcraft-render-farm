# EffectCraft Render Farm

EffectCraft 컴포지션 하나를 여러 PC에서 렌더링하는 별도 데스크톱 앱입니다. **호스트**가 작업을 배분하고 최종 MP4를 만듭니다. **클라이언트**가 호스트의 로컬 IP로 TCP 연결을 시작합니다. 원본 컴포지션의 FPS와 해상도는 변경하지 않습니다.

이 저장소는 EffectCraft 본체와 분리되어 있습니다. 프로젝트 파일을 읽기 위한 공개 Rust 라이브러리는 특정 커밋(`ef74d82902ba486891b02afa87e42963cc9b84cc`)에 고정합니다. 프레임 렌더링은 **각 PC에 설치된 EffectCraft의 CLI**를 사용하며, Farm 배포 파일에는 `effectcraft-cli`를 포함하지 않습니다. 호스트와 클라이언트의 EffectCraft 버전을 동일하게 맞추세요.

## 설치

1. 호스트와 모든 클라이언트에 [EffectCraft](https://github.com/storytold/effectcraft/releases/latest)를 먼저 설치합니다.
2. Farm 릴리스의 `effectcraft-render-farm-v버전-windows-x64.msi`를 실행합니다. 현재 사용자용 설치로, 기본 위치는 `%LOCALAPPDATA%\Programs\EffectCraft Render Farm`입니다. 시작 메뉴와 Windows의 설치된 앱 목록에 등록되며 제거 프로그램을 제공합니다.
3. 시작 메뉴의 **EffectCraft Render Farm**을 실행합니다. Windows App Paths 레지스트리(HKCU/HKLM, 32/64비트 뷰), 설치 제거 등록 정보, 기본 설치 폴더, 이전에 감지한 경로와 PATH에서 EffectCraft를 찾습니다. 해당 폴더에 `effectcraft.exe`와 `effectcraft-cli.exe`가 모두 있어야 합니다. 예전 Farm ZIP 옆의 CLI만 있는 폴더는 EffectCraft 설치로 인정하지 않습니다.
4. EffectCraft 또는 해당 CLI가 없으면 설치·복구 안내를 표시합니다. 사용자가 동의하면 공식 설치 페이지를 열고, 안내가 닫히면 Farm은 종료합니다. 렌더 화면이나 호스트는 시작하지 않습니다.

앱 실행 때마다 경로를 다시 감지합니다. 예전에 수동 지정했던 CLI 경로는 감지된 EffectCraft CLI로 갱신되며, Farm에서 CLI 파일을 직접 선택할 필요가 없습니다. Farm 설치·업데이트·제거는 EffectCraft 설치와 렌더 결과 폴더를 변경하지 않습니다. 한글은 운영체제에 설치된 글꼴을 사용합니다.

**0.6.x ZIP에서 처음 넘어올 때는 MSI를 직접 실행해 설치하세요.** 0.6.x 업데이트 기능은 ZIP 전용이므로 이번 MSI 전환에는 수동 설치가 필요합니다. 0.7.0부터 후속 자동 업데이트도 MSI로 진행합니다. 0.7.0의 네트워크 프로토콜은 5이며, 0.5.x와 연결할 수 없습니다. 모든 PC의 Farm과 EffectCraft 버전을 맞추는 것을 권장합니다.

## 빌드

Rust 1.95 이상에서 `cargo build --release`로 앱을 빌드합니다. Windows MSI는 다음 명령으로 만듭니다.

```powershell
pwsh packaging/windows/package.ps1
```

빌드 스크립트는 x64 GUI 실행 파일을 정적 CRT로 빌드하고, .NET 8 런타임에서 실행하는 WiX 5.0.2 포터블 도구를 SHA-256 검증 후 사용합니다. WiX를 시스템에 설치하지 않습니다. 출력은 `target/release-v버전/`의 MSI와 `SHA256SUMS.txt`입니다. 패키지 파일 목록은 Farm 실행 파일, README, 두 라이선스로 고정되어 있으며 EffectCraft 실행 파일과 CLI를 포함하지 않습니다.

## 사용 순서

1. 호스트 PC에 `.ecproj`와 렌더에 필요한 미디어·글꼴을 준비합니다. 호스트는 선택한 컴포지션과 하위 컴포지션의 참조 파일을 검사합니다. 각 클라이언트에도 같은 버전의 Render Farm 앱과 EffectCraft를 설치합니다.
2. 호스트 PC에 프레임을 저장할 폴더를 만듭니다. 클라이언트에서 접근 가능한 공유 폴더일 필요는 없습니다. 예시 프로젝트의 PNG 시퀀스에는 호스트에서 약 17GB가 필요합니다.
3. 호스트에서 프로젝트를 선택하면 컴포지션 목록을 자동으로 읽습니다. 드롭다운에서 렌더할 컴포지션을 고르면 해당 컴포지션의 **작업 영역**이 기본 렌더 범위로 설정됩니다. 범위 바의 양쪽 손잡이나 시작·끝 프레임 숫자로 범위를 조정하고, 버튼으로 작업 영역 또는 전체 컴포지션으로 되돌릴 수 있습니다. 끝 프레임은 **미포함**입니다. 프레임 저장 폴더, 수신 IP:포트, 접속 암호(8자 이상), 동시 사용할 PC 수(호스트 포함), 최종 MP4 경로를 입력합니다. 구간 분배의 기본값은 선택한 범위를 PC 수의 8배 이상으로 잘게 나누는 **자동**(구간당 최대 120프레임)이며, **프레임** 또는 **퍼센트**로 구간 크기를 직접 조정할 수 있습니다. **호스트 열기**를 누릅니다.
4. 클라이언트에서 호스트 IP:포트와 접속 암호를 설정하고, GPU 가속 사용 여부를 확인합니다(기본 활성화). 로컬 렌더 엔진 경로는 자동으로 표시됩니다. 같은 LAN의 호스트를 자동 검색하거나 고정 IP를 직접 입력할 수 있습니다. **호스트에 연결**을 누르면 작업 지시를 기다립니다.
   `127.0.0.1`은 클라이언트 자신을 가리킵니다. 호스트가 다른 PC라면 호스트 PC의 고정 LAN IP를 입력하세요. 호스트 화면에 **호스트 실행 중** 및 **TCP 수신 중**이 표시된 다음 연결합니다.
5. 호스트에서 사용할 클라이언트를 선택하고 **렌더 시작**을 누릅니다. 작업 차례가 된 클라이언트에 호스트가 전송용 프로젝트, 참조 미디어·이미지 시퀀스·글꼴을 보내고 SHA-256으로 확인합니다. 클라이언트는 지시된 구간을 로컬 임시 폴더에서 렌더링하며, 완성된 PNG부터 호스트로 전송합니다. CLI 렌더링과 네트워크 전송이 겹쳐 진행됩니다. 호스트는 프레임을 검증해 저장합니다. 동시 PC 수를 넘는 클라이언트는 대기합니다. 작업이 끝나거나 연결 오류가 나면 클라이언트의 임시 프로젝트·소스·프레임을 삭제합니다.
6. 모든 프레임을 확인하면 호스트가 FFmpeg에 PNG 시퀀스를 직접 전달해 NVENC 우선으로 최종 MP4를 출력합니다. 원본 오디오는 EffectCraft로 별도 믹싱해 포함합니다. FFmpeg를 찾지 못하면 기존 EffectCraft 출력 경로로 전환합니다. **원본 `.ecproj`는 변경하지 않습니다.**

호스트는 전체 프레임 렌더 진행률과 각 PC의 현재 구간·누적 완료 프레임을 표시합니다. 클라이언트도 자신이 렌더링 중인 구간의 진행률을 표시합니다. 연결·렌더 오류를 포함한 작업 기록은 `%APPDATA%\EffectCraft\render-farm\render-farm.log`에 저장됩니다. 기록은 5MB에 도달하면 `.old.log`로 교체됩니다.

호스트의 프로젝트 경로·출력 설정과 클라이언트의 호스트 IP·암호·감지된 CLI 경로 등은 종료 후에도 각 PC의 EffectCraft 사용자 설정 폴더에 저장됩니다. 호스트는 고정 IP를 기준으로 클라이언트별 사용 여부를 기억합니다. 암호는 이 PC의 설정 파일에 일반 텍스트로 저장되므로, 신뢰하는 사용자 계정에서 사용하세요.

## 모니터와 성능 옵션

- **작업 설정 / 렌더 모니터** 탭에서 설정과 진행 화면을 전환합니다. 모니터에는 전체 진행률, 경과 시간, 처리 FPS, 예상 잔여 시간, PC별 구간·수신량·전송 속도와 색상별 프레임 타임라인이 표시됩니다. 예상 잔여 시간은 현재 작업 속도를 기준으로 한 추정치이며, 소스 배포와 최종 인코딩 시간은 포함하지 않습니다.
- **선택 프레임 시험 렌더**로 시작 전에 범위 안의 프레임을 최대 480px로 확인합니다. 완료 프레임 탐색에서는 호스트에 저장된 프레임을 열 수 있습니다. PC별 미리보기는 가장 최근에 완성된 프레임을 보여 줍니다.
- **자동 분배와 작업 지원**: PC가 작업을 마치면 공용 대기열에서 다음 구간을 가져갑니다. 자동 균형 옵션이 켜져 있으면 PC별 이전 처리 속도와 목표 작업 시간(기본 30초)을 이용해 대기 구간을 나눕니다. 대기열이 비면 진행 중인 구간의 미완료 뒤쪽을 준비된 대기 PC에 넘깁니다. 기존 PC는 호스트가 정한 경계까지 렌더링한 뒤 CLI를 종료하고, 지원 PC는 그 다음 프레임부터 시작합니다. 완료된 프레임을 중복 전송하지 않습니다. 구간 공유 시 CLI가 미리 계산한 뒤쪽 프레임은 폐기될 수 있습니다.
- **전송 최적화**: 1MiB 읽기 버퍼, TCP_NODELAY, 렌더와 업로드의 동시 진행, 기본 200ms 작업 확인을 사용합니다. 수신한 PNG는 SHA-256과 PNG 구조를 확인한 뒤 확정합니다. 기본값은 OS 쓰기 캐시를 사용합니다. 전원 장애 대비가 필요하면 **수신 프레임마다 디스크 동기화**를 켜세요. 미디어와 프로젝트는 항상 디스크 동기화합니다.
- **추가 옵션**: 자동 균형, 목표 구간 시간(5~300초), 최대 시도(1~10회), 미리보기 사용 여부와 갱신 주기(1~30초), 프레임 감지 주기(50~2000ms), Best/Draft, H.264 비트레이트(100~200,000kbps), 오디오 포함, 프레임 디스크 동기화. GPU는 각 PC에서 선택합니다(0.8.0부터 기본 활성화). FPS와 해상도는 유지합니다. Draft는 검토용이며 효과 품질이 달라질 수 있습니다. 다른 품질의 프레임은 같은 출력 폴더에 혼합할 수 없습니다.
- **상세 로그**: 밀리초 UTC 타임스탬프, INFO/WARN/ERROR/DEBUG, 작업 배정·지원·복구, 소스 전송량과 시간, 프레임별 검증·저장, 렌더 속도, CLI 오류, 최종 영상 출력 결과를 기록합니다. 화면에는 최근 2,000건을 보관하며 검색, DEBUG 필터, 표시 로그 복사를 지원합니다. 전체 기록은 기존 로그 파일과 회전 파일에 저장됩니다. 접속 암호는 기록하지 않습니다.

구간을 작게 만들면 느린 PC 때문에 생기는 마지막 대기 시간이 줄지만 CLI 시작 비용이 늘어납니다. 무거운 프로젝트에서는 프레임/퍼센트 분배로 구간을 늘릴 수 있습니다. 미리보기 생성 비용이 큰 프로젝트는 갱신 주기를 늘리거나 끌 수 있습니다. 실제 시간 단축 폭은 프로젝트, PC, 디스크와 LAN 성능에 따라 달라집니다.

## GPU 렌더링과 NVENC 우선 MP4 출력 (0.8.0)

- 프레임과 시험 프레임 렌더링은 각 PC에서 EffectCraft의 `--gpu`를 기본으로 사용합니다. 이전 버전에서 GPU가 꺼져 있던 설정도 0.8.0을 처음 실행할 때 한 번 활성화합니다. 이후 사용자가 GPU 옵션을 끄면 그 선택을 유지합니다. GPU와 효과의 지원 범위는 설치된 EffectCraft에 따릅니다.
- 호스트에 FFmpeg가 있으면 완성된 PNG를 EffectCraft 합성 단계로 다시 보내지 않고 직접 인코딩합니다. `h264_nvenc`를 먼저 사용하고, 드라이버·GPU·해상도 등의 이유로 실패하면 오류를 기록하고 `libx264`의 `veryfast` 프리셋으로 재시도합니다. NVIDIA GPU가 없는 호스트도 CPU 경로를 사용할 수 있습니다.
- FFmpeg는 EffectCraft 설치 폴더, PATH, Windows의 `C:\FFMPEG\bin`과 일부 기본 설치 위치에서 자동 감지합니다. **성능 · 품질 · 미리보기 옵션**에서 실행 파일을 직접 지정할 수도 있습니다. FFmpeg가 없으면 [공식 다운로드 안내](https://ffmpeg.org/download.html)를 참고하세요. MSI에 FFmpeg와 EffectCraft CLI를 포함하지 않습니다. NVENC를 지원하는 FFmpeg 빌드와 호환 NVIDIA 드라이버가 필요합니다.
- **최종 MP4: FFmpeg로 직접 인코딩 · NVIDIA NVENC 우선**은 기본으로 켜집니다. 이 옵션을 끄거나 FFmpeg를 찾지 못하면 기존 EffectCraft H.264 출력을 사용합니다. 프레임 렌더링의 GPU 옵션과 최종 MP4의 NVENC 선택은 별개입니다.
- NVENC는 `p4`, VBR, 설정한 비트레이트를 사용합니다. 프레임 수와 FPS는 선택 구간과 원본의 유리수 FPS를 그대로 사용하며 픽셀 종횡비를 유지합니다. 출력 색상은 BT.709 limited range입니다. 홀수 해상도는 크기를 바꾸지 않고 CPU YUV444 경로를 사용합니다.
- 오디오가 있는 프로젝트는 원본 프로젝트의 선택 구간을 EffectCraft에서 WAV로 믹싱한 뒤 AAC로 포함합니다. 원본 프로젝트 경로에서 믹싱하므로 상대 경로의 오디오도 유지합니다. 출력은 임시 MP4에 기록한 뒤 성공 시 최종 이름으로 확정합니다. 원본 PNG는 유지합니다.
- 선택된 인코더, NVENC 실패 원인과 CPU 전환, 인코딩 프레임 수·경과 시간은 화면과 로그에 표시합니다. PNG 디코딩과 색상 변환은 CPU에서 수행하므로 전체 출력 시간이 모두 GPU 처리 시간으로 바뀌는 것은 아닙니다.

## 자동 업데이트

앱을 시작하면 GitHub의 최신 정식 릴리스를 한 번만 자동으로 확인합니다. 상단의 **업데이트 확인** 버튼으로 즉시 확인할 수도 있습니다. 실행 시 자동 확인은 체크박스로 끌 수 있습니다. 시험판·초안·현재보다 낮거나 같은 버전은 업데이트하지 않습니다.

새 버전이 있으면 현재/새 버전, 변경 내용, GitHub 릴리스 링크를 보여 줍니다. **동의하고 업데이트 · 재시작**을 누른 경우에만 MSI 다운로드와 설치가 시작됩니다. **나중에** 또는 창 닫기를 선택하면 설치하지 않으며, **업데이트 보기**로 다시 열 수 있습니다. 렌더링·호스트·클라이언트·시험 렌더가 실행 중이면 적용할 수 없습니다.

자동 설치는 Windows x64를 지원합니다. 릴리스에는 `effectcraft-render-farm-v버전-windows-x64.msi`와 GitHub 자산의 `sha256:` digest가 필요합니다. 다운로드 크기·SHA-256과 MSI 컨테이너를 검사하고, 설치 도우미가 MSI의 ProductName·UpgradeCode가 Farm과 일치하는지 확인한 뒤에만 앱을 종료합니다.

설정 저장 후 설치 도우미가 준비됐는지 확인하고 앱을 종료합니다. 도우미는 종료를 기다렸다가 Windows Installer로 **Farm만** 업데이트하고 다시 실행합니다. EffectCraft와 그 CLI는 업데이트 패키지에 포함하지 않으며 교체하지 않습니다. Windows Installer의 업그레이드·롤백을 사용하고, 실패 시 기존 Farm이 있으면 다시 엽니다. 결과는 사용자 설정 폴더의 `update-result.txt`로 다음 실행에 전달됩니다. 임시 폴더의 `effectcraft-farm-update-*`에 설치 프로그램과 `setup.log`가 남습니다. 다른 실행 중인 프로세스로 인해 Windows 재시작이 필요하면 안내를 표시합니다. 호스트와 클라이언트는 각각 동의하여 업데이트해야 합니다.

## 복구와 제한

- 호스트는 프레임 구간을 겹치지 않게 배정하고 PNG 시작·끝 구조를 확인합니다. 실패한 구간은 기본 최대 세 번 시도합니다(설정에서 1~10회 조절). 연결이 끊긴 PC의 구간은 다시 대기열에 넣습니다.
- 같은 설정과 호스트 프레임 폴더로 다시 시작하면 구간의 일부만 완료돼도 검증된 프레임을 이어서 사용합니다. `effectcraft-farm.json`이 프로젝트, 컴포지션, FPS, 해상도, 렌더 범위, Best/Draft 품질을 묶습니다. 다른 작업에는 별도 폴더를 사용하세요.
- 중지 요청 시 진행 중인 구간은 마친 뒤 멈춥니다. 최종 MP4가 이미 있으면 덮어쓰지 않고 시작 전에 오류를 표시합니다.
- 현재 버전은 마지막 프레임이 일부만 있는 경우를 포함해 최대 100,000프레임 컴포지션을 지원합니다. 최종 출력 형식은 H.264 MP4입니다.
- 전송 대상은 선택한 컴포지션과 하위 컴포지션이 참조하는 프로젝트 미디어·이미지 시퀀스·활성 프록시·파일 기반 글꼴입니다. CLI에 내장된 글꼴은 별도 전송하지 않습니다. 외부 스크립트나 플러그인이 자체적으로 읽는 파일은 자동으로 파악할 수 없습니다. 클라이언트에는 전송 파일을 담을 만큼의 임시 디스크 공간이 필요합니다. 비정상 종료로 임시 폴더가 남으면 운영체제의 임시 폴더에서 `effectcraft-farm-worker-*`를 확인하세요.
- 통신은 로컬 네트워크용 암호 인증 TCP입니다. 전송 내용은 암호화되지 않으므로 신뢰할 수 없는 네트워크에서는 VPN을 사용하세요.
- 자동 검색은 호스트가 열려 있을 때 UDP 9779 포트에 대한 LAN 브로드캐스트와 응답을 사용합니다. 같은 네트워크 대역에서 UDP가 허용되어야 하며, 라우터·방화벽이 브로드캐스트를 차단하면 고정 IP를 직접 입력하세요. 검색 응답에는 PC 이름과 TCP 포트만 포함되며 접속 암호는 전송하지 않습니다.
- 연결이 거부되면 호스트에서 프로젝트·출력 경로·접속 암호를 모두 채운 뒤 **호스트 열기**를 눌렀는지, 호스트 PC의 IP와 TCP 포트가 맞는지 확인하세요. 연결 시간이 초과되면 두 PC의 LAN 연결과 호스트 PC 방화벽의 TCP 수신 허용을 확인하세요. 계속 실패하면 양쪽 PC의 위 로그 파일에서 연결 오류 문구를 확인하세요.

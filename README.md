# EffectCraft Render Farm

EffectCraft 컴포지션 하나를 여러 PC에서 렌더링하는 별도 데스크톱 앱입니다. **호스트**가 작업을 배분하고 최종 MP4를 만듭니다. **클라이언트**가 호스트의 로컬 IP로 TCP 연결을 시작합니다. 원본 컴포지션의 FPS와 해상도는 변경하지 않습니다.

이 저장소는 EffectCraft 본체와 분리되어 있습니다. 프로젝트 파일을 읽기 위해 [EffectCraft](https://github.com/storytold/effectcraft)의 공개 Rust 라이브러리를 특정 커밋(`ef74d82902ba486891b02afa87e42963cc9b84cc`)에 고정해 사용합니다. 렌더링에는 동일한 버전의 `effectcraft-cli`가 필요합니다.

## 빌드

Rust 1.95 이상에서 `cargo build --release`로 이 앱을 빌드합니다. EffectCraft CLI는 고정한 커밋에서 별도로 빌드합니다.

```text
git clone https://github.com/storytold/effectcraft.git
cd effectcraft
git checkout ef74d82902ba486891b02afa87e42963cc9b84cc
cargo build --release -p effectcraft-cli
```

Windows용 릴리스 ZIP에는 `effectcraft-farm.exe`와 `effectcraft-cli.exe`가 함께 들어 있습니다. 소스에서 빌드할 때는 두 실행 파일을 같은 폴더에 두거나 앱에서 CLI 파일을 지정하세요.
호스트와 모든 클라이언트에는 같은 버전의 Render Farm 앱을 설치하세요. 0.2.0의 연결 프로토콜은 0.1.0과 호환되지 않으며, 버전이 다르면 연결 시 오류를 표시합니다.
앱 화면의 한글은 운영체제에 설치된 글꼴을 사용합니다. Windows에서는 맑은 고딕을 자동으로 불러옵니다.

## 사용 순서

1. 모든 PC에 **동일한 내용의** `.ecproj`, 동일한 EffectCraft CLI 버전, 프로젝트에서 사용하는 미디어와 글꼴을 준비합니다. 앱은 프로젝트 파일의 SHA-256이 일치하는지 확인합니다. 호스트와 클라이언트는 작업 시작 전에 선택한 컴포지션과 하위 컴포지션이 참조하는 미디어 파일·이미지 시퀀스 프레임·글꼴을 각 PC에서 검사하고, 누락 항목을 표시하며 렌더를 시작하지 않습니다. 상대 미디어 경로는 각 PC의 프로젝트 파일 위치를 기준으로 해석합니다.
2. 모든 PC에서 읽고 쓸 수 있는 공유 프레임 폴더를 만듭니다. Windows에서는 `\\HOST-PC\frames` 같은 UNC 경로를 사용할 수 있습니다. 예시 프로젝트의 PNG 시퀀스에는 약 17GB가 필요합니다.
3. 호스트에서 프로젝트를 선택하면 컴포지션 목록을 자동으로 읽습니다. 드롭다운에서 렌더할 컴포지션을 고르고, 공유 폴더, 수신 IP:포트, 접속 암호(8자 이상), 렌더 범위, 동시 사용할 PC 수(호스트 포함), 최종 MP4 경로를 입력합니다. 끝 프레임은 **미포함**이며 `0`은 컴포지션 끝입니다. 구간 분배의 기본값은 선택한 범위를 PC 수로 균등 분할하는 **자동**이며, **프레임** 또는 **퍼센트**로 구간 크기를 직접 조정할 수 있습니다. **호스트 열기**를 누릅니다.
4. 각 클라이언트에는 호스트 연결과 렌더 준비 항목만 표시됩니다. 동일한 프로젝트와 공유 폴더, 같은 접속 암호를 입력합니다. 클라이언트 화면은 같은 LAN에서 열린 호스트를 자동 검색하며, 목록에서 선택하면 고정 IP:포트가 입력됩니다. 검색되지 않으면 호스트의 **로컬 IP:포트**(예: `192.168.1.10:9778`)를 직접 입력할 수 있습니다. **호스트에 연결**을 누르면 호스트가 선택한 컴포지션을 클라이언트에 전달하고, 클라이언트가 리소스를 확인한 뒤 프레임 작업을 요청합니다.
5. 호스트에서 사용할 클라이언트를 선택하고 **렌더 시작**을 누릅니다. 호스트도 렌더에 참여할 수 있습니다. 동시 PC 수를 넘는 클라이언트는 대기합니다. 완료된 프레임과 진행률이 호스트에 표시됩니다.
6. 모든 프레임을 확인하면 호스트가 PNG 시퀀스를 임시 프로젝트의 영상 레이어로 사용하고 원본 오디오를 유지해 최종 MP4를 출력합니다. **원본 `.ecproj`는 변경하지 않습니다.**

프로젝트 경로, 호스트 IP, 암호, 범위, PC 수, 구간 크기, 최종 파일 경로 및 클라이언트 사용 여부는 종료 후에도 각 PC의 EffectCraft 사용자 설정 폴더에 저장됩니다. 호스트는 고정 IP를 기준으로 클라이언트별 사용 여부를 기억합니다. 암호는 이 PC의 설정 파일에 일반 텍스트로 저장되므로, 신뢰하는 사용자 계정에서 사용하세요.

## 복구와 제한

- 호스트는 프레임 구간을 겹치지 않게 배정하고 PNG 시작·끝 구조를 확인합니다. 실패한 구간은 최대 세 번 재시도합니다. 연결이 끊긴 PC의 구간은 다시 대기열에 넣습니다.
- 같은 설정과 공유 폴더로 다시 시작하면 검증된 완료 구간을 이어서 사용합니다. `effectcraft-farm.json`이 프로젝트, 컴포지션, FPS, 해상도, 렌더 범위를 묶습니다. 다른 작업에는 별도 폴더를 사용하세요.
- 중지 요청 시 진행 중인 구간은 마친 뒤 멈춥니다. 최종 MP4가 이미 있으면 덮어쓰지 않고 시작 전에 오류를 표시합니다.
- 현재 버전은 프레임 경계에서 끝나는 최대 100,000프레임 컴포지션을 지원합니다. 최종 출력 형식은 H.264 MP4입니다.
- 사전 검사는 파일 존재 여부와 글꼴 이름을 확인합니다. 미디어의 내용이 같은지, 글꼴 파일의 버전이 같은지까지 비교하지 않으며 파일이나 글꼴을 자동 복사하지 않습니다. 모든 PC에서 동일한 소스와 글꼴을 준비하세요.
- 통신은 로컬 네트워크용 암호 인증 TCP입니다. 전송 내용은 암호화되지 않으므로 신뢰할 수 없는 네트워크에서는 VPN을 사용하세요.
- 자동 검색은 호스트가 열려 있을 때 UDP 9779 포트에 대한 LAN 브로드캐스트와 응답을 사용합니다. 같은 네트워크 대역에서 UDP가 허용되어야 하며, 라우터·방화벽이 브로드캐스트를 차단하면 고정 IP를 직접 입력하세요. 검색 응답에는 PC 이름과 TCP 포트만 포함되며 접속 암호는 전송하지 않습니다.

## 라이선스

이 앱의 코드는 MIT 또는 Apache-2.0 중 하나를 선택해 사용할 수 있습니다. 렌더링 엔진과 프로젝트 라이브러리는 위에 링크한 EffectCraft 저장소에서 가져오며 해당 라이선스를 따릅니다. 운영체제의 한글 글꼴은 실행 시 읽을 뿐 배포 파일에 포함하지 않습니다.
